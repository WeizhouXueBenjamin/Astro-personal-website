# 业务定义与决策

本文维护当前业务选择与事实边界。实现情况以代码为准；历史经过仅在需要追溯时查阅[审计索引](project-audit.md)。技术契约见[工程约定](engineering.md)，视觉实现见[设计规范](design-system.md)。

## 定位与受众

网站用于求职与职业展示，主要受众为招聘人员、招聘经理和技术评估工程师。方向为 **Automation / Control Systems & Software Integration**：突出 PLC/SCADA、工业自动化、系统集成与软件开发，现场技术经验作为实践优势，不单独定位为 IT Support。

网站正文使用 NZ English；业务文档与 instructions 使用中文，代码标识与技术术语保留英文。项目规则用 Markdown 表达，优先适配 Codex，也供其他 AI 阅读。

访问路径是：首页识别方向 → Projects 查看贡献和证据 → About 了解背景 → 查看英文 CV 或联系；Blog 补充技术思考与表达能力。

## 页面职责

| 页面 | 内容与后续动作 |
| --- | --- |
| Home `/` | 精简身份与定位、显式精选项目、背景入口和集中联系区；避免复制整份履历 |
| About `/about` | 单一职业背景页，展示经历、教育与能力；过长经历默认折叠 |
| Projects `/projects`、`/projects/[slug]` | 统一卡片进入独立 Hybrid Case Study，呈现个人角色、成果媒体、技术过程、验证及限制 |
| Blog `/blog` 与文章详情 | 技术文章和项目复盘，支持技术阅读；正式发布范围由工程契约统一维护 |

主导航为 Home、About、Projects、Blog。旧 `/experience` 跳转 `/about#work-experience`，旧 `/gallery` 回首页；两者不进入导航和 sitemap。Gallery 暂缓，不建立新内容模型。静态跳转依靠 HTML meta refresh 与链接，不宣称返回 HTTP 301/302。

## 已确认的展示选择

- 统一为克制的深色工程作品集；浅色主题需要另行实现。
- 首页保留 Hero 背景粒子，遵循减少动效偏好；具体外观与加载边界由设计规范维护。
- 英文 CV 在新标签页打开 PDF，不强制下载；与联系入口共同支持招聘方下一步动作。
- Projects 使用单文件 MDX，正文直接阅读；当前不显示分类筛选，不根据项目数量自行切换。列表与详情构图由设计规范维护。
- Automation / SCADA 优先；精选、排序及发布过滤的具体行为只在工程约定中维护。
- 使用自定义域名根路径和 GitHub Pages 发布；域名配置、覆盖方式及 URL 约束由工程约定维护。

这些选择约束获授权任务中的实现，不要求在每个任务中完成全部页面改造。

## 内容真实性

- 可以基于已提供事实精简、翻译和润色，不改变职责范围与指标含义。
- 不补造雇主、学历、职称、日期、任职状态、客户、用户规模、性能比例、认证、推荐引文或项目生命周期状态。
- 发现来源冲突时指出并向所有者确认；仓库内容作为输入不等于已独立核实。
- 缺少可选内容就省略模块或使用真实空状态；缺少必需事实时询问，不发布占位信息。推荐材料还必须具备真实文件、引文与公开使用范围。
- 两项仿真不得改写为生产馈线投运、工厂现场调试或受聘自动化岗位经历；已有软件与现场技术岗位保留真实职称。
- 区分已实现、实际验证、书面观察和未来计划，不因技术栈频次推断熟练度，不把自然时间跨度写成累计工作年限。
- 示例留在文档或隔离测试中，不混入正式集合。Starter Kit 文章保持草稿，不作为作者正式文章展示。

## 产品边界

采用静态站点和现有外部联系方式，无需登录即可浏览。CMS、账号、数据库、联系表单后台、评论和追踪分析属于新增需求。

核心内容和链接在禁用 JavaScript 时仍可阅读、使用；交互作为增强。移动端必须支持导航、正文、证据与联系入口，不能只以桌面截图验收。
