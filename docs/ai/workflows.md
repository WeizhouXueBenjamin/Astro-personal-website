# AI 任务流程与验收

从[项目入口](../../AGENTS.md)选择当前任务需要的资料。清楚的自然语言需求足够，不要求所有者填写固定表单；复杂任务先明确目标、范围、事实、约束与可观察验收条件。

## 任务执行

1. 检查实现、工作区差异和相关规范，区分当前行为、已确认目标与历史记录。
2. 缺少影响定位、内容真实性、信息架构或范围的决定时集中询问；继续推进可独立完成的部分。
3. 复用现有布局、集合和组件完成范围内的完整改动；已确认事项不反复询问。
4. 根据受影响行为验证并审查 diff，只同步确实改变的契约或规则。
5. 交付结果、实际验证、未验证边界及缺少输入；区分原有问题与新增问题。

## 前端与 UI 修改前的设计检查

每次前端或 UI 修改前自动读取并结合 `distinctive-ai-design` Skill，按当前会话可用目录定位。已有明确方向时沿用[设计规范](design-system.md)，无需再次确认。

- 检查实际页面与现有改动，写一句希望强化的阅读或操作目标。
- 局部修复采用相关设计与交互检查；新视觉概念或重设计执行对应探索和评审流程。
- 在运行环境检查主操作、相关状态及真实截图。至少覆盖桌面、390px 和 320px，核对焦点、对比度、对齐、文字密度、导航遮挡、长标题/链接换行与横向溢出。
- 动效检查正常与减少动效偏好；核心内容检查禁用 JavaScript。颜色变化运行设计配对检查，不能用脚本结果代替实际页面状态。
- 按 Skill 条件使用独立评审或自查，优先修正最影响任务的 1–3 个问题后复核。截图缺失时明确视觉验证未完成；构建、功能和审美分别报告。
- 使用当时可用且获授权的工具，不要求为检查引入 Playwright。

## 指导文档写入审查

适用于 AGENTS、仓库 Skill、README 中的 AI 指导和领域规范。写入前完成以下判断，常规修订无需逐次审批：

| 审查项 | 判定 |
| --- | --- |
| 必要性 | 是否影响后续任务决策，是否有长期价值 |
| 依据 | 是否来自明确用户要求、真实契约变化或可复现证据 |
| 落点 | 哪份文档负责该规则，是否已有同义要求 |
| 处理方式 | 不写入、替换、合并、新增或归档 |
| 影响 | 是否改变原意、存在事实冲突或超出授权范围 |

- 优先修改原规则。新决定替代旧决定时一并移除失效要求，其他入口改为链接，避免同义改写形成第二份定义。
- 用户改变业务决定时更新业务规范；实现契约变化时同步对应工程说明和模板。不能从临时反馈、单次工具故障或普通修复经过推导永久规则。
- 新永久规范需说明适用范围；新 Skill 需有独立可复用流程，普通导航不单独建立 Skill。代码和配置可直接回答的事实优先链接来源。
- 写入后审查 diff 的重复、矛盾、遗漏、无关修改与体积变化。超出预算先去重或移出历史，不能为通过检查自行提高预算。
- 交付简述写入依据、唯一落点、替换/删除内容和实际验证，不建立逐次审查日志。
- 自动检查负责机械问题；规则价值、语义重复、真实性和授权仍按本节审查。

## 历史记录维护

普通任务结果留在会话或已有 PR，不例行追加“本轮实施记录”。仅在重大迁移、兼容结论或专项审计需要独立证据时新增日期记录，包含来源、实际验证与未验证边界。

既有历史证据保存在[归档索引](project-audit.md)指向的文件中；不改写旧结果冒充当前验证，不默认加载归档。项目素材来源和仍有效的维护步骤留在项目展示规范。

## 验证选择

可执行命令以[package.json](../../package.json)为准。所有测试内容必须隔离，不写正式集合。

| 受影响范围 | 执行与观察 |
| --- | --- |
| 代码或网站内容 | `pnpm run build`，再验证实际受影响行为 |
| 集合、发布、列表、导航或跳转 | 加 `pnpm run verify:site`；核对草稿、日期/排序、空集合、可选值与旧地址 |
| 正式构建产物、域名或公开资源 | build 后运行 `pnpm run verify:output`，核对链接、metadata、RSS、sitemap 与 robots |
| 颜色或前景/背景配对 | 加 `pnpm run verify:design`，并检查实际文字、控件及焦点 |
| 前端或 UI | 按上文设计检查，验证键盘、窄屏、无 JavaScript；动效变化检查减少动效 |
| 指导文档 | `pnpm run verify:ai-docs`，核对事实和 diff；纯文档不运行无关站点测试 |
| 文档检查器或其测试 | 加 `pnpm run test:ai-docs` 与 build，覆盖隔离样例及只读行为 |

文档检查扫描入口、README、领域规范和历史归档的本地 Markdown 链接与标题锚点；代码示例中的假链接不参与。活跃文档的 `pnpm run` 命令对照 scripts，归档命令保留历史语义。长段落重复仅提醒。

体积预算由[检查脚本](../../scripts/verify-ai-docs.mjs)集中定义：入口、各领域文档、审计索引及活跃指导集分别受限；README 和历史归档不计入指导体积。检查器无写入或自动修复，不验证外部网址或代码引用片段的真实性。

站点场景验证使用临时内容与 dev 服务，不等于浏览器交互验证。设计脚本只覆盖已列 token 配对，不代表完整 WCAG 审核；build 不代表完整类型检查。不得声称运行了不存在的 lint/check/typecheck，或把本地成功写成线上发布成功。
