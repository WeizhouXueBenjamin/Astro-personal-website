## 受众与访问路径

主要受众是招聘人员、招聘经理及参与技术评估的工程师。同行读者可通过 Blog 深入了解作者；本阶段的功能优先级围绕职业展示安排。

推荐访问路径：

1. 首页快速说明身份、工程方向和值得继续阅读的内容。
2. 招聘方进入 Projects 了解具体问题、贡献、技术选择和结果。
3. 招聘方进入合并后的 About 了解职业经历、教育与技能背景。
4. 有兴趣的访客通过邮件或现有职业社交账号发起联系。
5. Blog 提供技术思考与表达能力的补充证据。

首页已接入显式精选项目、背景入口及联系方式。后续继续围绕这条路径组织内容，避免新增没有明确职责的页面。

## 目标信息架构

| 入口 | 核心问题 | 内容边界 | 主要后续动作 |
| --- | --- | --- | --- |
| Home `/` | 你是谁，擅长什么，为什么继续看？ | 精简身份与定位、精选证据和主要入口；避免复制整份履历 | 查看作品、阅读背景、联系 |
| 合并后的 About | 你的背景、经验与能力是否匹配？ | 职业介绍、经历、教育与技能；经历数据只维护一份 | 查看相关作品、联系 |
| Projects `/projects` | 你具体做过什么，贡献是什么？ | 真实项目、角色、问题、方案、结果，以及已提供的源码/演示链接 | 查看真实演示、源码、联系 |
| Blog `/blog` 与文章详情 | 你如何思考、解决与表达技术问题？ | 技术文章与项目复盘；公开内容遵循一致的发布规则 | 阅读相关文章、查看相关作品 |

合并页面沿用 `/about` 地址，主导航为 Home、About、Projects、Blog。新建页面前先判断内容是否属于已有领域。

旧 `/experience` 生成跳转到 `/about#work-experience` 的静态页；旧 `/gallery` 生成回到首页的静态页。这两页不出现在导航和 sitemap 中。当前静态托管依靠 HTML meta refresh 和可点击链接，不宣称服务端返回 HTTP 301/302。实现依据见 [Astro 官方路由文档](https://docs.astro.build/en/guides/routing/#redirects)。

## 内容真实性

- AI 可以根据已提供事实精简、翻译、组织和润色，保持职责范围与指标含义。
- 不自行补充雇主、学历、日期、任职状态、客户名称、用户规模、性能提升比例或推荐引文。
- 仓库中的事实是本次生成的输入依据，不等于已独立核实；发现相互矛盾时指出冲突，向所有者确认。
- 缺少可选内容时省略对应模块或显示真实空状态。缺少必需的业务事实时集中询问；不要把待填写内容作为真实内容发布。
- 可独立运行的示例应明确标识用途并放在文档中；不能混入正式内容集合冒充作者成果。
- 技术栈出现频次不能解释为熟练度；自然时间跨度不能未经定义就解释为累计工作年限。
- 项目说明区分工程场景、工具与仿真环境、个人实现、联调或测试证据及限制；只用已提供的事实填入现有 schema，不为凑齐描述补写协议、设备或性能。
- 两项个人仿真案例不能转述为生产馈线投运、工厂现场调试、专业认证或受聘的自动化工程岗位经历。已有软件与技术岗位保留真实职称。
- Starter Kit 文章作为草稿保留，不作为作者的正式技术文章展示。

## 体验边界

- 访问者无需登录即可浏览公开内容。
- 当前采用静态站点和已有外部联系方式；账号系统、CMS、数据库、联系表单后台、评论与追踪分析都属于新增需求。
- 现有视觉基线是深色页面及共享 CSS token。先延续现有设计；如任务涉及主题扩展，再明确范围并实现相应 token 与交互。
- 重要信息与链接应在没有客户端 JavaScript 时可阅读和使用；交互作为增强。
- 移动端保持导航、正文和联系入口可用，不能只以桌面截图为验收依据。

## 业务验收

后续代码任务按受影响范围选择验收，不要求每次实现全部目标：

- 首页文案能够表达已确认的目标岗位方向，并提供通往作品和背景的入口。
- About 与 Experience 合并后只有一个完整职业背景入口；更新经历不需要同时修改两份数据。
- 项目列表来自真实集合；没有项目时如实展示为空，不生成虚构成果。
- 所有公开文章出口使用一致的 draft 规则。
- 联系方式来自共享配置，可选外链缺失不会产生无效按钮。
- 不将本地构建通过等同于内容完整、视觉验收通过或线上发布成功。
